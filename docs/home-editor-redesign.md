# 에디터 중심 홈 개편 기획서

> 브랜치 `feat/editor-centric-home` · 작성 2026-11-13 · **상태: 2026-11-19 시안 A·B와 스위처 삭제(채택 안 함). 아래는 기록용.** 홈은 기존 `HomeScreen` 하나.
> 현재 배포본(main, https://main-redesign.vercel.app/)은 그대로 두고, 같은 앱 안에서 시안을 바꿔 가며 비교한다.

## 0. 시안 보는 법 (먼저 읽기)

| 보는 방법 | 설명 |
|---|---|
| 화면 왼쪽 아래 스위처 | **현재 / A 런처형 / B 에디터 우선형** 중 하나를 누른다. 고른 값은 이 브라우저에 기억된다 |
| URL 파라미터 | `?home=a`, `?home=b` — 이 링크를 공유하면 받는 사람도 같은 시안이 열린다. 파라미터가 없으면 기존 홈 |
| 캡처·발표용 | `?switcher=0`을 붙이면 스위처가 숨는다 (예: `?home=b&switcher=0`) |

로컬 실행: `npm run dev` → http://localhost:5173/?home=a

### 새 시안을 추가하려면

1. `src/app/components/home/variants/homeVariants.ts`의 `HOME_VARIANTS`에 한 줄 추가 (예: `{ id: "c", label: "C …", desc: "…" }`)
2. 같은 폴더에 `HomeXxx.tsx`를 만든다. props는 `HomeVariantActions`(shared.tsx), 편집기·프리셋 데이터는 `editorEngines.ts`를 그대로 쓴다
3. `App.tsx`의 `screen === "home"` 분기에 `homeVariant === "c"` 줄을 추가한다

기존 홈(`HomeScreen`)과 그 하위 컴포넌트는 손대지 않는다. 시안에서 공통 컴포넌트를 바꿔야 하면 기존 홈에 영향이 없는지 먼저 확인한다(CLAUDE.md 유지보수 원칙).

## 1. 배경 — 서비스 방향이 바뀌었다

| | 지금까지 | 앞으로 |
|---|---|---|
| 핵심 행동 | 템플릿 고르기 → AI가 만들어 줌 | **에디터에서 직접 만들고**, 필요하면 AI에게 시킨다 |
| 템플릿의 역할 | 시작점 그 자체 (홈의 대부분) | 에디터 **왼쪽 패널**에서 고르는 재료 |
| AI의 역할 | 별도 생성 흐름 | 에디터 **오른쪽 패널**의 조수 (만들기 + 고치기) |
| 도구 범위 | 문서·발표·엑셀·이미지·영상 | + 피그마형 디자인, 포토샵형 사진, 일러스트형 벡터, PDF |

참고 모델은 Canva다. 템플릿은 옆에서 고르고, 가운데는 에디터, 오른쪽은 "말하면 다 해 주는" AI.

### 지금 홈의 문제

1. **진입 방식 세 가지가 경쟁한다.** 프롬프트, 편집기 아이콘 줄, 템플릿/작업 카드가 모두 홈에 있고, 무엇이 주인공인지 흐리다.
2. **편집기 줄이 부가 기능처럼 보인다.** "무료 편집기 바로 열기"가 작은 회색 라벨 + 아이콘이라, 새 방향의 1순위 행동인데 가장 약하게 보인다.
3. **분류 기준이 섞여 있다.** 도구모음에 파일 형식(HWP·DOCX·XLSX)과 결과물(카드뉴스·상세페이지·랜딩페이지)이 같은 단계로 나열돼 있다. 도구가 늘면 카드가 20개를 넘는다.
4. **"인기 템플릿"과 "작업별로 시작하기"가 겹친다.**
5. **재방문 사용자를 위한 자리(최근 작업)가 없다.** 에디터 중심 서비스는 "이어서 하기"가 가장 많이 쓰이는 행동이다.

## 2. 정보 구조 — 편집기와 결과물을 나눈다

가장 먼저 합의해야 할 결정이다. 시안 A·B 모두 이 구조를 전제로 한다(데이터: `variants/editorEngines.ts`).

### 2-1. 편집기(엔진) — 9개

| 그룹 | 편집기 | 여는 파일 | 지금 연결 | 비고 |
|---|---|---|---|---|
| 문서 | 문서 | DOCX | 워드 | |
| | 한글 | HWP·HWPX | 한글 | |
| | PDF | PDF | — (준비 중) | 신규 |
| | 시트 | XLSX·CSV | 엑셀 | |
| | 슬라이드 | PPTX | PPT | |
| 디자인 | **디자인** | — | 이미지 | 신규. 피그마형 캔버스 |
| | **포토** | JPG·PNG·PSD | 레이어 분리 | 신규. 포토샵형 |
| | **벡터** | SVG·AI | — (준비 중) | 신규. 일러스트형 |
| 영상 | 영상 | MP4·MOV | 영상 | |

**합치는 것 (도구모음 기준)**
- 딸깍 포토 + 딸깍 보정 + 레이어 분리 → **포토** 하나. 보정·레이어 분리는 포토 안의 모드.
- UI 디자인 + 레이아웃 + 카드뉴스 + 상세페이지 + 이미지 디자인 + 디자인 슬라이드 → **디자인** 하나 + 크기 프리셋.
- 랜딩페이지 → 디자인 캔버스로 만든다면 프리셋, 별도 웹 빌더라면 편집기로 추가. **(미결정 — 6장)**

**이름 원칙**
- "포토샵 같은", "피그마 같은"처럼 프로 도구를 떠올리게 하는 표현은 쓰지 않는다. 주 사용자는 일반 사용자다.
- 고급 기능은 같은 편집기 안에서 단계적으로 보여 준다.

### 2-2. 결과물(프리셋) — 편집기를 "알맞은 크기로" 여는 입구

| 프리셋 | 편집기 | 규격 |
|---|---|---|
| 카드뉴스 | 디자인 | 1080×1350 |
| 상세페이지 | 디자인 | 860×가변 |
| 포스터·광고 | 디자인 | A4 · SNS |
| 발표자료 | 슬라이드 | 16:9 |
| 보고서 | 문서 | A4 |
| 공문·신청서 | 한글 | A4 |
| 숏폼 영상 | 영상 | 9:16 |

프리셋은 편집기 카드 수를 늘리지 않고 "뭘 만들지"로 들어오는 사람을 받는다. 홈에서는 칩으로 보여 준다.

### 2-3. 파일 열기 = 자동 연결

파일을 끌어다 놓거나 고르면 **확장자를 보고 편집기를 정해서 바로 연다.** 사용자에게 "어떤 편집기로 열까요?"를 묻지 않는다. 기존 장점인 "채팅 없이 파일을 바로 열어 편집"이 홈에서 바로 보이게 된다.

## 3. 원칙

1. **어느 길로 들어와도 에디터에 도착한다.** 프롬프트 → 에디터 + AI 패널이 이어서 작업. 템플릿 → 에디터. 파일 → 에디터.
2. **홈은 고르는 곳이 아니라 보내는 곳(런처).** 본격적인 템플릿 탐색은 에디터 왼쪽 패널에서 한다.
3. **모든 편집기는 같은 셸을 쓴다.** 편집기가 9개가 돼도 배우는 비용은 하나.
4. **처음 온 사람과 다시 온 사람의 홈은 다르다.** 처음: 프롬프트·프리셋·템플릿 / 다시: 최근 작업.

## 4. 시안 A — 런처형 (`?home=a`)

파일: `variants/HomeLauncher.tsx`

```
┌──────────────────────────────────────────┐
│        무엇을 만들거나 열어 볼까요?          │
│  ┌────────────────────────────────────┐  │
│  │ 만들 것을 적어 주세요…               │  │  ← 프롬프트 + 드롭존이 한 덩어리
│  │ [📎 파일 열기] [✨ 도우미]   [AI로 만들기]│  │
│  └────────────────────────────────────┘  │
│   카드뉴스 · 상세페이지 · 포스터 · 발표자료…   │  ← 프리셋 칩
├──────────────────────────────────────────┤
│ 새로 만들기          [문서][한글][PDF]      │  ← 편집기 9개, 3×3 카드
│                     [시트][슬라이드][디자인]  │
│                     [포토][벡터][영상]      │
├──────────────────────────────────────────┤
│ 최근 작업            ▢ ▢ ▢ ▢               │
├──────────────────────────────────────────┤
│ 템플릿으로 시작하기   ▢▢▢▢▢▢ → 전체 보기     │  ← 한 줄로 축소
└──────────────────────────────────────────┘
```

- **장점:** 지금 홈과 흐름이 비슷해 전환 부담이 적다. 모바일에 그대로 맞는다. 처음 온 사람도 헤매지 않는다.
- **단점:** 홈과 에디터가 여전히 다른 화면이라 "왼쪽 템플릿 / 오른쪽 AI" 사용법을 에디터에 들어가서야 처음 본다.
- **검증할 것:** 편집기 카드를 3×3으로 크게 둘지, 한 줄짜리 작은 아이콘으로 둘지(지금 홈 방식). 최근 작업을 템플릿보다 위에 둘지.

## 5. 시안 B — 에디터 우선형 (`?home=b`)

파일: `variants/HomeEditorFirst.tsx`

```
┌──────────┬────────────────────────┬──────────┐
│ 템플릿    │  새 작업 만들기           │ 딸깍 AI   │
│ [전체|문서 │  ┌ 파일 끌어다 놓기 ┐     │ 안내 문구  │
│ |디자인|영상]│  문서  [문서][한글][PDF]…│ 추천 요청 3│
│ ▢ ▢      │  디자인 [디자인][포토][벡터]│          │
│ ▢ ▢      │  영상  [영상]            │          │
│ ▢ ▢      │  크기로 시작하기 칩       │ [입력창 ↑] │
└──────────┴────────────────────────┴──────────┘
```

- **장점:** 홈 자체가 에디터와 같은 3단 구조라, 들어오는 순간 "왼쪽에서 고르고 오른쪽에 시킨다"를 익힌다. 홈에서 에디터로 넘어갈 때 화면이 크게 바뀌지 않는다.
- **단점:** 정보가 한 화면에 많다. 1024px 미만에서는 세로로 쌓여서(AI → 새로 만들기 → 템플릿) A와 비슷해진다. 히어로 문구 같은 브랜드 인상이 약하다.
- **검증할 것:** 처음 온 사람이 무엇부터 할지 아는지. AI 패널을 기본으로 펼칠지 접을지.

## 6. 함께 정해야 할 것 (미결정)

| # | 질문 | 영향 |
|---|---|---|
| 1 | 디자인·포토·벡터는 **편집기 3개인가, 한 캔버스의 모드인가?** | 한 캔버스면 편집기 카드가 7개로 줄고 홈이 더 단순해진다 |
| 2 | 랜딩페이지는 디자인 캔버스인가, 별도 웹 빌더인가? | 프리셋이냐 편집기냐 |
| 3 | 핵심 지표는 **신규 생성 수**인가, **재방문 편집**인가? | 홈 최상단을 템플릿·프롬프트로 할지, 최근 작업으로 할지 |
| 4 | 프롬프트를 보내면 어디로 가나? | 지금 시안은 기존 검색 결과 화면으로 간다. 목표는 "알맞은 편집기 + AI 패널이 초안 생성" |
| 5 | PDF·벡터 출시 전에는 홈에 "준비 중"으로 보여 줄까, 숨길까? | 지금 시안은 "준비 중" 배지로 보여 준다 |

## 7. 에디터 셸 (홈 다음 단계)

홈 시안이 정해지면 편집기 쪽을 맞춘다. 지금 hwpx 에디터(왼쪽 템플릿 · 가운데 문서 · 오른쪽 딸깍 AI)가 기준이다.

```
[상단: 파일명 · 저장 상태 · 실행취소 · 공유 · 내보내기 — 모든 편집기 같음]
┌────┬─────────┬─────────────────┬──────────┐
│레일 │ 왼쪽 패널 │ 캔버스 + 상황별 툴바 │ 딸깍 AI   │
└────┴─────────┴─────────────────┴──────────┘
```

| 편집기 | 왼쪽 레일 탭 (첫 탭은 항상 템플릿) |
|---|---|
| 문서·한글 | 템플릿 · 서식 · 목차 · 업로드 |
| 디자인 | 템플릿 · 요소 · 텍스트 · 업로드 · 레이어 |
| 포토 | 템플릿 · 레이어 · 조정(보정) · 필터 · AI 분리 |
| 벡터 | 템플릿 · 도형·펜 · 레이어 · 색상 |
| 영상 | 템플릿 · 미디어 · 자막 · 오디오 |

- AI는 오른쪽 패널(큰 작업)과 **선택 영역 옆 "AI로 수정" 버튼**(작은 수정) 두 곳에 둔다.
- 디자인·포토는 리본 툴바 대신 **상황별 툴바**(선택한 객체에 맞는 도구만)로 캔버스를 넓게 쓴다.

## 8. 시안의 한계 (실제 기능이 아님)

- **최근 작업**은 캐러셀 표지로 만든 예시다(화면에 "예시 데이터" 표시).
- PDF·벡터는 편집기가 없어 누르면 "준비 중" 안내만 뜬다. 디자인은 이미지 편집기로, 포토는 레이어 분리 편집기로 임시 연결했다.
- 템플릿 표지를 누르면 카드뉴스만 전용 화면으로 가고, 나머지는 전체 템플릿 화면으로 간다.
- 시안 A·B에서는 첫 방문 온보딩이 뜨지 않는다(온보딩 대상 요소가 기존 홈에만 있다).
- 편집기 아이콘은 기존 에셋을 임시로 썼다. 벡터는 이미지 아이콘, 디자인은 앱 소개 아이콘, PDF는 맞춤법 아이콘.
