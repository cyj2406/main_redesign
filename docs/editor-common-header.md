## 2. 문제

1. **두 줄 헤더가 서로 겹친다.** 공통 상단 바 + 도구 안쪽 줄에 같은 기능이 반복: 공유(템플릿 편집기·레이아웃은 안쪽에도), 🔔(보정은 안쪽에도), 테마 ☀(포토·보정·영상 안쪽), 앱 아이콘(포토·벡터 안쪽 메뉴바 맨 앞).
2. **도구마다 버튼 세트·순서가 다르다.** 템플릿 편집기는 공유가 안쪽에, 다른 도구는 위에. "새로 만들기"는 템플릿 편집기에만, "레이어 분리"는 벡터에만 상단에.
3. **"코멘트"와 "0"이 따로**(코멘트 남기기 버튼과 개수 버튼이 나란히) — 역할이 헷갈린다.
4. **텍스트 버튼이 많아 길다** — "딸깍 AI · 템플릿 · 코멘트 · 0 · 공유 · 기록"이 앱 이름 옆에 이어져 파일 이름이 들어갈 자리가 없다(지금 대부분 파일 이름이 안 보임).
5. **좌우 패널을 다 열면 캔버스가 화면의 1/3** — 템플릿(왼쪽 400px) + AI(오른쪽 400px) + 서비스 레일.

## 3. 공통 헤더 구조 (제안)

```
┌───────────────────────────────────────────────────────────────────────────────────────────────┐
│ ‹  [아이콘] 딸깍 포토 ▾ / 가을 신메뉴 포스터            [도구 슬롯]     ✨ 💬3 🕘 │ ▷  [내보내기] [공유] 🔔 (나) │
└───────────────────────────────────────────────────────────────────────────────────────────────┘
   ① 정체성(왼쪽)                                           ② 도구 슬롯   ③ 패널 토글    ⑤ 결과물   ④ 알림·프로필(오른쪽 끝)
```

| 영역 | 내용 | 규칙 |
|---|---|---|
| ① 정체성 | ‹ 나가기(딸깍 홈) · 앱 아이콘 · **앱 이름 ▾**(다른 딸깍 편집기로 바로 이동, 아이콘 격자) · / · **파일 이름**(더블클릭 이름 바꾸기) · **저장 상태**(평소엔 없음, "저장 중…" / "저장 못 함"일 때만) | 모든 도구 같음. 새로 만들기: UI 디자인은 탭 줄 ＋, 문서 편집기(한글·워드·엑셀·PPT·PDF·영상·이미지)는 파일 탭 없이 템플릿 패널 "빈 문서"·사이드바 |
| ② 도구 슬롯 | 그 도구에만 있는 **핵심 행동 1~2개**(벡터 "레이어 분리" 등). 없으면 비움 | 많아지면 도구 안쪽 메뉴로. 상단은 2개까지 |
| ③ 패널 토글(아이콘) | ✨ 딸깍 AI · 💬 코멘트 목록(읽지 않음 배지) · 🕘 기록 — **오른쪽 패널을 여는 버튼은 오른쪽에** | 도구가 지원하는 것만 보인다. 순서 고정 |
| ④ 알림 | 🔔 — AI 작업 완료·멘션. **프로필 바로 옆 오른쪽 끝**(2026-11-19 이동: 파일 작업 버튼 사이에 끼어 있었다. 내 계정 소식이라 Google Docs·Notion·Canva·Figma처럼 프로필 옆) | 도구 안쪽의 🔔는 없앤다 |
| ⑤ 결과물 | ▷ 미리보기/프레젠테이션(지원 시) · 💾 저장 · **공유**(테두리) · **다운로드**(채운 주요 버튼) · 맨 끝 내 프로필 | 다운로드가 없는 도구만 공유가 주요 버튼(아래 32, 2026-11-27 바뀜) |

- **템플릿은 상단에서 뺀다.** 왼쪽 패널을 여는 버튼이 오른쪽 위에 있으면 공간이 어긋난다. 도구 왼쪽 패널의 첫 탭으로(UI 디자인의 "파일·에셋·변수" 탭, Canva 왼쪽 사이드바 "디자인·요소·텍스트…"와 같은 방식).
- **저장·테마·🔔·앱 아이콘·공유는 도구 안쪽 줄에서 없앤다.** 저장은 자동 저장 + 상단 저장 상태로, 테마는 설정 › 화면 설정 한 곳.
- **도구 안쪽 메뉴바(파일·편집·…)는 남긴다**(포토·벡터·레이아웃처럼 전문 도구는 메뉴바를 기대한다). 다만 앱 아이콘을 빼고, 상단 헤더와 겹치는 항목(공유·저장·내보내기)은 메뉴에서만.
- 높이: 상단 48px, 도구 안쪽 줄 40px. 상단 바와 도구 줄 사이는 1px 선 하나.

## 6. 적용 순서(제안)

1. `EditorHeader`에 기능 조합을 넘기는 방식 추가(`capabilities: { ai, comments, history, present, export, share }`, `toolSlot`, `saveState`, 앱 전환 ▾).
2. 템플릿 편집기 5종(같은 화면이라 한 번에) — 안쪽 공유·저장·내보내기를 위로 올리고 템플릿을 왼쪽 탭으로.
3. 포토·벡터·레이아웃 — 안쪽 메뉴바의 앱 아이콘·테마 정리, 공유·내보내기 위로.
4. 보정·영상편집 — 내보내기를 주요 버튼으로, 안쪽 🔔·테마 제거.
5. 공통: 서비스 사이드바는 아이콘 레일로 붙임, 프로필은 오른쪽 끝 하나(서비스와 같은 메뉴, 크레딧 포함).

## 7. UI 디자인 적용 내용 (2026-11-19)

- `EditorHeader` props: `currentAppId` · `onSwitchApp` · `onNewFile` · `saveState` · `capabilities { present, export, share }` · `presentLabel` · `onExport` · `toolSlot` · `actions`(DockButtons) · `viewers`.
- 앱 이름 ▾ = **아이콘 격자(4×2)**(2026-11-19 변경, Google Workspace·Microsoft 365 앱 런처처럼). 홈 "편집기 바로 열기"와 같은 8개·같은 그림·같은 이름(`editor-shell/apps.ts`의 `EDITOR_APPS` 한 곳, 홈 줄도 이걸 쓴다). 지금 편집기는 브랜드 연한 바탕, 못 여는 도구는 흐리게 "준비 중"(`soon`, 2026-11-19 PDF 연결 뒤 지금은 없음). 예전 17개 글자 목록 + "새 파일"은 없앴다(새 파일은 탭 줄 ＋).
- 저장 상태(2026-11-19 다시 간소화): 평소(저장됨)엔 **아무것도 안 보인다**. 구름 아이콘은 뜻이 잘 안 읽혀(사용자 "있어야 하나") 없앴다. Figma·Canva처럼 자동 저장이 기본이라 표시하지 않고, "저장 중…"·"저장 못 함"일 때만 글자로 알린다. 안쪽 에디터가 저장 상태를 보여 주는 도구(한글·워드)는 헤더에 두지 않는다.
- UI 디자인 기능 조합: ▷ 프레젠테이션 · 공유(주요). 내보내기는 메인 메뉴에만(준비 중)이라 헤더에 버튼 없음. 도구 슬롯 없음.
- 크레딧: 프로필 메뉴의 크레딧 카드에서만 보여 준다(AI 입력창 아래 잔액·충전 줄은 2026-11-19에 뺌).
- 프로필: 헤더 오른쪽 끝 하나. **메뉴는 서비스 상단바와 같은 컴포넌트** `components/account/ProfileMenuButton`(2026-11-19, 크레딧 카드·튜토리얼·문의·커뮤니티·로그아웃까지 동일). 다른 화면으로 가는 항목(마이페이지·요금제 및 크레딧·튜토리얼)은 에디터를 닫고 가고, 설정·크레딧 내역은 에디터 위에 설정 모달. 공유 버튼 인원 배지 없음. 버전 기록은 🕘(아래 "9", 2026-11-19 구현). 홈 탭은 ✨만.

- **딸깍 AI는 글자 버튼(2026-11-19)**: 핵심 기능이라 아이콘(✨)만 두면 잘 안 보인다는 피드백. 패널 토글 중 AI만 "✨ 딸깍 AI" 글자 버튼(`DockTab.emphasized`)으로,

## 8. 아이콘 버튼 툴팁 (2026-11-19)

## 24. 버전 기록 다시 설계 (2026-11-20)

사용자: "기록이 너무 헷갈린다. 이름도, 밑에 정보(방금 · 나)도 뭐가 뭔지 모르겠다. 공유하면 내 기록만 보이는지 다른 사람 것도 보이는지?"

**참고한 서비스**
- Google 문서: 파일 하나에 기록 하나, 편집한 사람 모두의 변경이 이름과 시각으로 쌓인다. 버전에 이름을 붙일 수 있고 "이름 있는 버전만" 걸러 본다.
- Figma: 자동 체크포인트 + 직접 남긴 버전(제목 · 설명). 편집 권한이 있는 사람만 보고 되돌린다. https://help.figma.com/hc/en-us/articles/360038006754
- Genspark AI 문서 · 슬라이드: Save Point로 되돌리면 그 뒤 변경이 사라진다(우리는 따르지 않음). https://www.genspark.ai/helpcenter/ai-docs · https://www.genspark.ai/docs/ai_slides_faq

**규칙** (`VersionHistoryPanel`, 문서 편집기 6종 · UI 디자인 공통)
1. 줄 하나 = 그때 파일 상태. 제목은 그 상태를 만든 일: “AI 요청 문장”(26자에서 자름) · ○○ 템플릿으로 시작 · 직접 고침 · 새로 만듦. "직전 상태" · "되돌리기 전 상태" · "자동 저장" 같은 말은 쓰지 않는다.
2. 둘째 줄 = 누가 · 언제(최유정 · 오후 2:48 / 딸깍 AI · 오후 2:48). "나" · "방금" 대신 이름과 시각.
3. 지금 상태인 줄에 **현재** 뱃지. 처음에는 맨 위 줄.
4. **되돌리기는 줄을 만들지 않는다**(사용자 "되돌림도 꼭 기록해야 하나, 헷갈린다"). 고른 줄로 현재 뱃지만 옮겨 가고, 그 뒤에 고치면 맨 위에 새 줄이 생긴다. 아무 줄도 지우지 않아서 위의 버전으로 언제든 다시 돌아갈 수 있다.
5. [지금 상태 남기기] → 이름(안 적어도 됨)을 붙여 현재 줄을 **남긴 버전**으로 표시. 이름이 있으면 제목 자리에, 원래 제목은 둘째 줄 앞에. 위의 [전체 · 남긴 버전]으로 걸러 본다.
6. 공유한 파일은 함께 편집하는 사람 모두의 기록이 한 목록에 쌓인다(Google 문서 · Figma와 같음). 안내 문구: "함께 편집하는 사람 모두의 기록이 쌓여요. 되돌려도 다른 버전은 그대로 남아요." 보기 권한만 있는 사람에게는 기록을 보여 주지 않는다(실서비스 기준, 프로토타입은 공유 권한 미구현).

데이터: 문서 편집기는 `DocFile.hist`(바뀐 뒤 상태, 최대 30개) + `curId`. 예전 `versions`(바뀌기 전 상태)는 읽지 않는다. UI 디자인은 `Version.saved/savedName`, 현재 = 지금 doc과 같은 줄. 예전 "되돌리기 전 상태" · "…버전으로 되돌림" 줄은 목록에서 뺀다.

7. **기록이 비어 있지 않게**(사용자가 빈 패널을 보고 고장으로 여김): `hist`가 비어 있으면(새 파일, 예전 방식으로 저장된 파일, 편집기 안에서 직접 친 글만 있는 파일) 지금 상태를 한 줄로 보여 준다. 빈 문서는 "새로 만듦", 내용이 있으면 마지막 원인(○○ 템플릿으로 시작 등). 이 줄에 [지금 상태 남기기]를 하면 실제 기록으로 들어간다.

8. **[지금 상태 남기기]는 남기고 탭은 뺌**(사용자 "최대한 심플한 플로우", 그 뒤 "원래 딸깍넷 편집기에 있던 기능이라 넣어 둬야 할 듯"): 패널 머리 오른쪽의 작은 [🔖 지금 상태 남기기] 버튼(가운데 큰 버튼은 왼쪽 정렬 목록과 따로 놀아서 옮김), 누르면 머리 아래에 이름 칸(안 적어도 됨) → [남기기]. 남긴 줄은 이름이 제목 자리에, "남긴 버전" 뱃지, 원래 제목은 둘째 줄 앞에. [전체 · 남긴 버전] 탭은 없앴다. 안내 문구: "눌러서 그때로 되돌릴 수 있어요. 되돌려도 다른 버전은 그대로 남아요." 안내, 날짜, 줄 글자는 모두 왼쪽 24px 선에 맞춘다.

- **숨김 버그**: 눈을 끄면 핀만 숨고 열린 스레드 팝오버는 그대로 떠 있었다. 이제 숨김이면 팝오버도 띄우지 않는다. 목록에서 항목을 눌러도 숨김을 풀지 않고 목록 안에서 연다.
  - 안내 문구 "캔버스에서 숨김 중. 코멘트 모드에서는 보여요"는 문서 편집기에서 실제 동작과 달라 "문서에서 코멘트를 숨겼어요. 목록에서는 계속 볼 수 있어요"로(자리 이름은 문서 · 시트 · 슬라이드 · PDF · 캔버스). 눈 버튼 툴팁도 "문서에서 코멘트 숨기기"처럼 자리 이름을 쓴다(`CommentListPanel` `surface` · `hiddenNote`).
- **UI 디자인 편집기도 같은 규칙**: `DesignFile`이 열린 스레드를 `onOpenThreadChange`로 셸에 알리고, 셸의 코멘트 목록이 `FileApi.threadView(t)`(동작 · 멤버 · 위치)로 목록 안에 그린다. 동작은 누르는 순간의 최신 상태로 부른다(되돌리기 스냅숏이 한 박자 늦지 않게). 숨김이면 코멘트 모드여도 핀과 팝오버를 모두 감춘다(예전엔 코멘트 모드에서 숨김을 무시했다).

## 32. 다운로드를 주요 버튼으로 (2026-11-27)

요청: "다운로드가 더 강조되어야 하지 않을까". 미리캔버스처럼 다운로드를 오른쪽 끝 채운 버튼으로.

## 33. 주요 버튼을 편집기별로, 다운로드 창에서 공유 알리기 (2026-11-27)

요청: "다운로드 강조", 이어서 "협업 코멘트가 있으면 공유 안에 넣어야 하나, 새 서비스라 모르지 않을까", "최대한 UI 안에서 해결".

- **다운로드를 공유 안에 숨기지 않는다.** 다운로드는 누구나 아는 기능이고, 처음 배워야 하는 건 공유와 코멘트다. 아는 기능을 모르는 기능 안에 넣으면 핵심 작업(파일 받기)이 막힌다(Canva 방식은 이미 익숙한 사용자 기준).
- **채운 버튼은 편집기별로**(`EditorHeader` `primary`): 문서 계열(한글 · 워드 · 엑셀 · PPT · PDF · 이미지 · 영상)은 다운로드, UI 디자인 · 보드는 공유(`primary="share"`). 채운 버튼은 항상 오른쪽 끝 하나. 고른 쪽이 없으면 남은 쪽이 채운 버튼.
- **다운로드 창 맨 아래 한 줄**(`ExportPopover` `onShare`): "파일 대신 공유하면 받는 사람이 바로 코멘트를 남길 수 있어요 [공유하기 ›]". 누르면 다운로드 창을 닫고 공유 창을 연다. 다운로드는 대개 누군가에게 보내려고 누르니 그 순간에 협업을 알린다. 튜토리얼 단계를 늘리지 않고 화면 안에서 알게 하는 장치.
  - 링크는 "초대받은 사람만" 열 수 있어 [링크 복사]가 아니라 공유 창(초대)을 연다. 링크 공개 범위가 바뀌면 문구를 다시 볼 것.
  - 형식이 하나라 창 없이 바로 받는 PDF에는 이 줄이 없다.
- 남은 결정: 저장 버튼을 둘지(자동 저장과 안쪽 에디터 저장과 겹침), 안쪽 에디터 파일 메뉴의 내려받기 정리(`docs/editor-overlaps.md`).

## 34. 코멘트 목록: 답글 미리보기 · 이전·다음 · 돌아올 때 자리 유지 (2026-11-27)

- **마지막 답글 한 줄**: 답글이 있으면 첫 코멘트 아래에 [작은 아바타] 이름 + 내용 한 줄(넘치면 말줄임). 읽지 않았으면 진하게. 답 하나 확인하려고 들어갔다 나오지 않게. 위치 줄의 "새 답글: 이름"은 이 줄과 겹쳐 뺐다.

## 38. 💾는 "지금 상태를 버전 기록에 남기기" (2026-11-27)

요청: "저장은 자동 저장으로 해 버리는 거야? 그럼 버전 기록의 의미가 없어지는 것 같아서".

- 자동 저장과 버전 기록은 하는 일이 다르다. 자동 저장은 마지막 상태 하나를 계속 덮어쓰고(작업이 날아가지 않게), 버전 기록은 돌아갈 수 있는 시점을 여러 개 남긴다(Google Docs · Figma도 둘 다 둔다).
- 문제는 지금 기록에 줄이 생기는 경우가 AI 결과, 템플릿, [이름 붙여 남기기]뿐이라는 것. 직접 고친 내용은 자동 저장이 덮어써서 그 사이 상태로 못 돌아간다. 그리고 💾는 자동 저장을 한 번 더 하는 것뿐이라 눌러도 아무것도 안 남았다.
- 바꾼 것(이미지 · 영상 · UI 디자인, 💾가 있는 편집기): 💾나 ⌘S를 누르면 저장과 함께 지금 상태인 줄을 **남긴 버전**으로 표시한다(기록 패널 [이름 붙여 남기기]와 같은 일, 이름 없이). 기록이 없으면 지금 상태를 새 줄로. 토스트 "저장했어요. 버전 기록에 남겼어요."
  - 코드: 문서 편집기 `markSaved(name)`(`saveNow`), UI 디자인 `saveCurrent(fileId, "")`.
- 남은 일(개발 협의): 직접 고친 내용 자동 체크포인트(몇 분 손을 떼거나 파일을 닫으면 그 사이 변경을 "직접 고침" 한 줄로 묶기), 문서 편집기는 안쪽 에디터 버전 기록과 합치기(`docs/editor-overlaps.md` 2번).

## 41. 💾를 파일 이름 옆으로 (2026-11-27)

## 42. 버전 기록: [이름 바꿔 남기기] 빼고 더블클릭으로 이름 바꾸기 (2026-11-27)

요청: "이름 바꿔 남기기? 굳이? 저장 버튼이 있는데? 더블클릭하면 이름 바꿀 수 있게, 좀 더 사용하기 편한 UI로". "24"의 8번(현재 줄을 누르면 [이름 붙여 남기기])을 바꿨다.

- **남기기는 상단 💾(⌘S)만.** 패널 안 [이름 붙여 남기기 · 이름 바꿔 남기기] 버튼과 이름 칸 + [남기기] 폼을 뺐다. 현재 줄은 할 일이 없어 눌러도 고르지 않는다. 다른 줄을 누르면 지금처럼 [이 버전으로 되돌리기].
- **이름 바꾸기는 그 자리에서**: 제목을 더블클릭하거나, 줄에 마우스를 올리면 오른쪽에 나오는 ✏(키보드는 F2)를 누르면 제목이 입력칸으로 바뀐다. Enter · 바깥 클릭 = 저장, Esc = 취소. 파일 이름 바꾸기(상단 제목)와 같은 방식.
  - 이름을 붙이면 그 줄은 "남긴 버전". 이름을 지우면 원래 제목(템플릿으로 시작 · AI 요청 문장 등)으로 돌아가고 남긴 버전 표시는 그대로. 토스트 "이름을 바꿨어요." / "이름을 지웠어요."
  - ✏만 둔 이유: 더블클릭은 모르는 사람이 많아서, 마우스를 올리면 보이는 버튼을 같이 둔다(Figma · Google 문서 버전 이름과 같은 방식).
- **"남긴 버전" 뱃지는 흰 바탕 + 테두리**: 고른 줄(회색 바탕) 위에서 회색 뱃지가 바탕에 묻혀 글자만 떠 보였다.
- 코드: `VersionHistoryPanel` `onSaveNow(name)` → `onRename(id, name)`. 문서 편집기는 기록이 아직 없어 보이는 줄(`now-…`)이면 지금 상태를 새로 남기며 이름을 붙인다.

## 43. 패널 버튼은 테두리 없이, 켜지면 회색 (2026-11-27)

"36"의 회색 묶음(버전 기록 · 코멘트를 회색 바탕 한 덩어리로, 열린 것만 흰 바탕)을 풀었다.

- 왜: 아무 패널도 안 열렸을 때 묶음 전체가 회색이라 "고른 게 없는 탭"처럼, 즉 비활성처럼 보였다. 덩어리가 커서 딸깍 AI와 무게도 비슷해 보였다. 템플릿만 흰 테두리 상자라 같은 성격 버튼끼리 모양이 셋으로 갈렸다.
- 지금: 템플릿 · 버전 기록 · 코멘트 모두 같은 규칙. 높이 40px, 테두리 없는 "아이콘 + 이름", 기본은 투명(hover 옅은 회색), 열리면 #f1f5f9 바탕 + 글자 #111827 · 굵게. 좁은 폭(HeaderWideContext 밖)에선 이름 없이 아이콘만, 이름은 툴팁 · aria-label에 남는다.
- 딸깍 AI는 그대로 옅은 파랑 단독 버튼(열리면 파란 테두리). 테두리 상자는 공유 · 다운로드에만 남는다. PDF의 [열기] 버튼도 템플릿 자리라 같은 모양.
- 안 읽은 배지 · 점의 테두리 링은 흰색(#fff)으로 바꿨다(바탕이 더 이상 회색이 아니라서).
