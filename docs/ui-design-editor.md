# 딸깍 UI 디자인 에디터 기획 (2026-11-13, v2)

홈 "편집기 바로 열기 > UI 디자인"으로 들어가는 피그마형 화면 디자인 편집기. dev 화면 캡처 3장에서 출발했고, v2에서 상단 바·코멘트·AI 패널을 다시 짰다.
코드: `src/app/components/uidesign/`(이 에디터) + `src/app/components/editor-shell/`(모든 에디터가 같이 쓸 셸).
**서버·실시간 동기화는 없다** — 구조와 로직을 정하는 프로토타입. 새로 열면 빈 파일.

## 1. 화면 구조

```
앱 사이드바(레일) │ 상단 바:  ‹  [아이콘] 딸깍 UI 디자인 / Untitled ▾ · 임시 보관함              🔔  (아바타들)  ▷  [공유]
                │ 레일 │ 파일 패널 │            캔버스             │ 속성 패널 │ 도크 패널(300) │ 도크 탭
                │      │ 페이지    │                               │ 디자인/   │ 딸깍 AI        │  ✨ AI
                │      │ 레이어    │      [하단 툴바 — 말풍선=C]     │ 프로토타입│ 또는 코멘트    │  💬 ●3
                │      │           │                               │           │ 또는 기록      │  🕘 기록
```

- **상단 바(공통 `EditorHeader`)**: 왼쪽 = 뒤로 · 앱 아이콘+앱 이름 / 파일 이름(더블클릭 이름 바꾸기) · 위치. 오른쪽 = 알림 · 참여자 아바타(나 + 초대 수락한 사람, 최대 3 + "+N") · 프레젠테이션 · **공유**.
  에디터마다 다른 것은 앱 아이콘·이름뿐. 높이 48.
- **오른쪽 도크(공통 `SideDock`)**: 맨 오른쪽 세로 탭 줄(40px, 항상 보임) + 그 왼쪽 패널(300px). 탭을 누르면 열고, 같은 탭을 다시 누르면 접는다.
  탭 = 딸깍 AI · 코멘트(읽지 않음 배지) · 기록. 패널은 **접어도 내용이 유지된다**(AI 작업이 계속 돌고 대화가 남음).
- **열고 닫기**(2026-11-13): ① 패널 머리 왼쪽 끝 **»** 버튼(모든 도크 패널 같은 자리) ② 오른쪽 탭을 다시 누르기 ③ **⌘J / Ctrl+J** = 딸깍 AI 열기·닫기(입력 중에도 동작).
  닫으면 캔버스·홈이 그 폭만큼 넓어진다(0.2초 전환). 마지막 상태(열림 탭/닫힘)를 기억해 다음에 그대로 연다. 닫혀 있는 동안 AI 작업이 끝나면 탭에 점.
- 속성 패널·파일 패널·하단 툴바는 v1 그대로(캡처 기준).

## 1-1. 홈 탭 (dev 홈 캡처 기준)

```
[딸깍 UI 디자인]        │ 최근 항목
[파일 및 템플릿 검색]   │ [새 디자인 파일  빈 캔버스로 시작] [새 보드  스티커 메모·도형·커넥터] [파일 열기  .figcraft·.svg 또는 이미지]
⌂ 최근 항목            │ 코드로 참여  [코드 또는 초대 링크] [참여]
▦ 템플릿               │ 시작하기 (6단계 안내, ✕로 닫기 — 다시 안 뜸)
                       │ 열린 파일 · 최근 파일
                       │ 템플릿으로 시작  [모바일 앱] [랜딩 페이지] [대시보드] [디자인 시스템 시작 키트]   [모든 템플릿 보기]
```

- 새 디자인 파일 = 빈 파일 탭을 연다. 새 보드 = 준비 중. 파일 열기 = 이미지(·.svg)는 새 파일에 이미지로 넣어 연다, .figcraft는 준비 중.
- 코드로 참여 = 코드·링크를 넣고 참여(서버 없음 — "참여 코드를 찾을 수 없어요" 안내).
- 템플릿 카드 = 미리보기 썸네일(실제 템플릿 내용을 축소해 그림) · 이름 · 설명 · 종류·크기. 누르면 그 내용으로 새 파일.
- 검색 = 파일 이름·템플릿 이름/설명으로 거른다. 왼쪽 "템플릿" = 템플릿 전체 목록.

### 1-2. 홈 v3 (2026-11-13) — "내가 한 작업"이 먼저 보이게 · 초록은 포인트만

**색 결정**: 초록(`EDITOR_ACCENT`)은 UI 디자인의 **제품 색**으로 남기되 홈에서는 한 곳(주요 행동 "새 디자인 파일")에만 칠한다.
v2처럼 행동 타일 3개·왼쪽 메뉴 선택·로고 글자를 모두 초록으로 칠하면 강조가 서로를 지워 정작 내 파일이 묻힌다.
Google Workspace(문서=파랑·시트=초록)처럼 앱마다 색은 다르지만, 목록 화면 자체는 무채색이고 색은 아이콘·주요 버튼에만 쓴다.
캔버스 안 선택·활성 도구·공유 버튼은 v2 그대로 초록.

**배치 결정**(Figma "최근 파일", Canva "최근 디자인" 참고 — 둘 다 첫 화면 대부분이 내 파일 썸네일):

```
최근 항목                                       [정렬: 최근 수정순 ▾] [▦ / ☰]
[＋ 새 디자인 파일](초록)  [새 보드]  [파일 열기]  [코드로 참여]        ← 한 줄, 높이 낮게
내 파일  ─────────────────────────────────────────────────────────
[썸네일][썸네일][썸네일][썸네일]   ← 실제 내용 축소 · 이름 · "3분 전 수정 · 프레임 2개"
                                     · 열린 탭 표시 · 읽지 않은 코멘트 배지 · ⋯(열기·이름 바꾸기·복제·삭제)
템플릿으로 시작 (작게, 아래로)
```

- 파일이 하나도 없을 때만 "시작하기" 안내와 큰 빈 상태를 보여 준다(있으면 안내는 숨김 — 내 파일 자리를 차지하지 않게).
- 파일 탭을 닫아도 파일은 "내 파일"에 남고, 다시 열면 그 상태로 열린다(실행 취소 기록은 닫을 때 사라짐).
- 이 브라우저에 저장한다(localStorage). 새로고침해도 남는다. 용량을 넘으면(큰 이미지 등) 저장만 건너뛰고 안내한다.
- 삭제는 메뉴 안에서 한 번 더 확인한다. 휴지통은 없다(되돌릴 수 없음을 확인 문구에 적는다).

### 1-3. 가로 단계 줄이기 (2026-11-19) — 캔버스 옆 7단 → 3단(AI를 열면 4단)

v2까지는 캔버스 주변에 세로 단이 7개였다: 앱 사이드바 · 에디터 레일(파일/에셋/변수) · 파일 패널 · **캔버스** · 속성 · AI 패널 · 도크 탭 줄.
같은 역할의 "목록 고르는 레일"이 세 번 반복되고, 화면 폭의 40% 가까이를 패널이 차지했다.

| 단 | v2 | v3 결정 | 근거 |
|---|---|---|---|
| 앱 사이드바(서비스 메뉴) | 아이콘 레일로 접혀 남음 | **에디터에서는 숨김**(집중 모드). 나가기는 상단 ‹ | Figma·Canva 에디터에는 서비스 전체 메뉴가 없다 |
| 에디터 레일(파일/에셋/변수) | 왼쪽 별도 44px 단 | **왼쪽 패널 맨 위 탭**으로 합침. 그 왼쪽 끝에 메인 메뉴 버튼 | Figma UI3 — 왼쪽 패널 상단에 메뉴 + "파일/에셋" 탭 |
| 왼쪽 패널 | 항상 보임 | **⌘\ 로 숨기기/보이기**(숨기면 캔버스 왼쪽 위에 다시 여는 버튼) | Figma "UI 숨기기" |
| 도크 탭 줄(AI·코멘트·기록) | 오른쪽 끝 48px 단 | **없앰. 상단 바 오른쪽 아이콘 3개**(✨ AI · 💬 읽지 않음 배지 · 🕘 기록) — 공유 왼쪽 | Google Docs(코멘트 기록 아이콘 + 공유), Claude in Chrome(툴바 버튼으로 사이드 패널 토글). v2의 "상단에서 뺀다"보다 단 수가 더 비싸다고 판단 |
| AI·코멘트·기록 패널 | 300px | 그대로(열었을 때만 단이 생김). 닫으면 0 | — |

결과: **왼쪽 패널 | 캔버스 | 속성** (+ 열면 AI/코멘트/기록 패널).

### 1-4. 메인 메뉴 (2026-11-19, dev 캡처 기준 · Figma 메인 메뉴 참고)
- 버튼 아이콘은 **☰**(2026-11-19 변경). 처음엔 dev의 로고 자리를 흉내 낸 @ 모양이었는데 메인 메뉴인지 알아보기 어렵다는 피드백 — 메인 메뉴에 가장 흔히 쓰는 햄버거 아이콘으로. 툴팁 "메인 메뉴: 파일·편집·보기 (⌘K로 검색)".

왼쪽 패널 왼쪽 위 로고 버튼 → 어두운 메뉴. 맨 위 **"액션…" 검색(⌘K)** — 하위 메뉴를 몰라도 이름으로 찾아 바로 실행.

지금 되는 것: 새 파일·이미지 열기·복제·파일 닫기 / 실행 취소·다시 실행·복제(⌘D)·삭제 / 확대·축소·맞추기·왼쪽 패널·코멘트 숨기기·딸깍 AI / 맨 앞·맨 뒤 / 굵게·정렬 / 부모 기준 정렬 6종 / 단축키 보기.
나머지(벡터·플러그인·라이브러리 등)는 흐리게 "준비 중". Esc 닫기, ↑↓ Enter 로 검색 결과 실행.

### 1-9. 탭 줄 첫 칸 = [▦ 파일] (2026-11-19)
- 사용자 "홈 버튼이 사이드바랑 왼쪽 상단에 2개라 겹친다": 탭 줄 맨 앞 ⌂(UI 디자인 홈 = 파일 목록)와 왼쪽 사이드바 레일 "홈"(딸깍 홈)이 같은 집 아이콘이라 같은 버튼처럼 보였다.

### 1-8. 양옆 패널 너비 (2026-11-19)
- 사용자 "양옆 바가 좁다": 레이어 패널 220 · 속성 패널 188px 고정이었다. Figma는 둘 다 약 240px에 끌어서 조절.

- 대가: 캔버스가 좁아진다(1440px 화면에서 AI 패널까지 열면 약 520px). 그래서 하단 툴바는 캔버스가 640px보다 좁으면 **작게(버튼 32 · 아이콘 16)** 바뀌어 패널 밑으로 들어가지 않는다. AI 패널을 » 로 접으면 다시 40 · 20.

## 3. 코멘트

### 3-1. 상태

- 스레드: `열림` ⇄ `해결됨`. 삭제는 첫 작성자만. 위치 옮기기는 첫 작성자만.
- 읽음: 사람마다 스레드별 `마지막으로 읽은 시각`. **다른 사람이 그 이후에 단 댓글이 있으면 "읽지 않음"**. 내 댓글은 읽지 않음을 만들지 않는다.

### 3-2. 동작

| 동작 | 결정 |
|---|---|
| 남기기 | 툴바 말풍선 또는 **⌘⌥M**(윈도우 Ctrl+Alt+M, 딸깍넷 공통 코멘트 단축키, 2026-11-20. C도 Figma 습관용으로 동작은 하지만 안내하지 않음) → 코멘트 모드(말풍선 커서, 요소 선택·이동 막힘, 위쪽 안내 띠). 캔버스 클릭 → 임시 핀 + 입력. Enter 등록 · Shift+Enter 줄바꿈 · 빈 채로 닫기/Esc = 버림. 모드에 들어가면 도크가 코멘트 탭으로 열린다(Figma) |
| 붙는 곳 | 클릭한 곳의 **최상위 프레임**에 붙는다 → 프레임을 옮기면 같이 움직임. 프레임 밖이면 캔버스 좌표. 프레임을 지우면 그 자리 캔버스 좌표로 남김 |
| **옮기기** | 핀을 **드래그**(3px 넘게 움직이면 옮기기, 아니면 클릭=열기). 놓은 자리의 최상위 프레임으로 다시 붙는다. 남의 핀은 옮길 수 없음(잡으면 "작성자만 옮길 수 있어요" 안내). 옮기기는 코멘트 모드가 아니어도 된다 |
| 열기 | 핀 클릭 = 스레드 팝오버(한 번에 하나). 열면 읽음 처리. 도크 목록 클릭 = 캔버스를 그 핀으로 옮기고(다른 페이지면 페이지 전환) 연다. Esc·✕ = 닫기 |
| 미리보기 | 핀에 마우스를 올리면(0.3초) 작성자·첫 줄·답글 수 카드. 열린 핀은 미리보기 없음 |
| **숨기기** | 도크 코멘트 패널의 눈 아이콘(⇧C도 동작은 하지만 2026-11-20부터 안내하지 않음) = 캔버스 핀 숨기기/보이기(데이터는 그대로, 목록은 계속 보임). 코멘트 모드에 들어가면 숨김과 상관없이 보인다. 숨김 중에는 패널 위에 "캔버스에서 숨김" 표시 |
| 해결 | ✓ = 해결 → 캔버스에서 사라지고 목록 "해결됨"으로. 해결된 걸 목록에서 열면 그 핀만 잠깐 보인다(흐리게), 다시 열기 가능 |
| **한번에 보기** | 도크 코멘트 패널: 열림/해결됨 탭 · "읽지 않음만" · 검색(본문·작성자) · 최신순. 항목 = 아바타·이름·#번호·시간·첫 댓글 두 줄·페이지·답글 수, 읽지 않으면 굵게+점. "모두 읽음으로 표시" |
| 배지 | 도크 코멘트 탭 = **읽지 않은 스레드 수**(없으면 열린 수를 회색 숫자로). 할 일(읽을 것)을 알리는 숫자는 하나만 |

### 3-3. 확대·축소할 때

- 핀은 **화면 크기 고정**(확대해도 32px), 위치만 붙은 지점을 따라간다. 팝오버도 핀을 따라가고, 핀이 화면 밖으로 나가면 팝오버는 숨었다가 돌아오면 다시 보인다.
- 핀끼리 겹치면(화면에서 28px 안) **묶음 원(숫자)** 으로 합친다 — 주로 축소했을 때. 묶음을 누르면 그 자리로 2배 확대해 풀어 준다. 읽지 않은 게 섞여 있으면 묶음에도 점.
- 임시 핀(작성 중)·열린 핀은 묶지 않는다.

### 3-4. 읽음 표시

- 핀: 읽지 않으면 오른쪽 위 **브랜드 블루 점**. 목록: 굵은 글씨 + 점. 도크 탭: 숫자 배지.
- 열거나 목록에서 누르면 읽음. "모두 읽음으로 표시"로 한 번에.
- 프로토타입 데모: 내가 새 스레드를 남기면 몇 초 뒤 예시 팀원(김하늘)이 답글을 단다 — 읽지 않음 흐름을 보여 주기 위한 가짜 답글(코드에 `DEMO_` 표시).

나중에: @멘션 알림(상단 🔔), 실시간 동기화, 이메일 알림, 해결 시 작성자에게 알림.

### 4-1. 입력창 정리 (Claude 입력창 참고)

v1 입력창의 아이콘 4개(첨부·에이전트 모드·자동 다듬기·브리프) 중 **첨부만 남긴다.** 역할이 불분명한 버튼은 뺐다.

```
┌──────────────────────────────────────────────┐
│ [선택: 배달앱 모바일 메인 ✕] [📎 로고.png ✕]   │  ← 맥락 칩 + 이번 메시지 첨부
│ 무엇을 할까요?                                 │
│ [+]  [▷▷ 자동 ▾]                         [↑] │
└──────────────────────────────────────────────┘
```

- **＋ 메뉴**(Claude의 ＋): 파일 올리기(이미지·PDF·.fig, 이번 메시지에만) · 프로젝트 파일에서 고르기 · 선택 영역을 이미지로 첨부.
  첨부는 입력창 위 칩으로 보이고 ✕로 뺀다. 이미지·PDF·.fig, 한 개 20MB, 메시지당 5개.
- **실행 방식 ▾**(Claude in Chrome의 "행동 전에 묻기/묻지 않고 실행"): `자동`(바로 캔버스에 그림) / `먼저 계획 보여 주기`(무엇을 할지 단계 목록을 먼저 보여 주고 [실행]을 눌러야 그림).
- 보내기 ↔ 작업 중 정지(■). Enter 보내기, Shift+Enter 줄바꿈.
- **대기열**(성격 급한 연속 요청 대비, Claude 대기 메시지 참고): 작업 중에 보낸 요청은 입력창 바로 위 **카드 한 장**에 쌓인다.
  카드는 **좌우로 넘겨 본다** — ‹ › 버튼 · 트랙패드/터치 가로 스와이프 · ←/→, 머리에 "대기 1/3", 아래 점 표시.
  카드마다 **↑ 바로 보내기**(지금 작업을 멈추고 이 요청 먼저 — 그린 데까지는 남김) · **✕ 빼기**. 2개 이상이면 "모두 지우기".
  **고치기는 두지 않는다**(빼고 다시 쓰면 된다 — 2026-11-13 사용자 결정). 최대 5개(넘으면 안내).
  작업 중 보내기 버튼 이름은 "대기열에 추가". 대기 중인 요청은 대화에 아직 올리지 않고, 실행될 때 말풍선이 된다.
- 모델 선택·음성 입력은 넣지 않는다(서비스가 고르는 값).

### 4-2. 프로젝트 파일·지침 (Claude 프로젝트 참고)

Claude 프로젝트의 "지식"처럼, **이 디자인 파일에서 AI가 모든 요청마다 참고하는 자료**. v1의 "브리프" 버튼을 이걸로 바꾼다(패널 머리의 [📁 프로젝트]).

| 항목 | 내용 |
|---|---|
| 지침 | 자유 글(예: "브랜드 컬러 #FF6B00, 모서리 16, 말투는 해요체"). 요청마다 자동으로 붙는다 |
| 파일 | 브랜드 가이드 PDF, 로고, 참고 화면 캡처, 디자인 시스템 .fig 등. 올리기·지우기·이름·크기·올린 날짜 |
| 용량 | 프로젝트 전체 용량 막대(예시 100MB) |
| 표시 | 지침이나 파일이 있으면 맥락 칩 줄에 "프로젝트 자료 N개 참고 중" 표시 — 지금 무엇을 참고하는지 보이게 |
| 범위 | 원래는 파일(문서) 단위. **프로토타입은 에디터 세션 단위**(AI 패널이 하나라서) — 파일 단위 저장은 서버 연동 때. 팀 프로젝트는 나중 |

### 4-3. 대화 관리 (Claude 사이드 패널 참고)

- 패널 머리: 대화 제목(첫 요청으로 자동) · **기록**(이 파일의 지난 대화 목록, 눌러 다시 열기) · **새 대화** · 접기.
- 작업 결과(2026-11-13 정리): 단계 요약 한 줄("요소 24개 추가, 단계 6개 ›" — 눌러 펼침) · 결과 설명 · **결과 카드**(만든/고친 요소 이름 · 크기 · 요소 수, 누르면 캔버스에서 선택해 보여 줌 — 별도 "선택해서 보기" 버튼 없음) ·
  바닥 줄에 "크레딧 N 사용"(조용히) + **최신 결과에만 ↶ 되돌리기**(이전 결과는 그 뒤 편집과 꼬일 수 있어 ⌘Z로).
  **평가(👍/👎)·복사 버튼은 두지 않는다** — 받아서 쓸 곳이 없고 결과마다 반복돼 시끄럽다. 의견이 필요해지면 세션 단위로 가끔 묻는다(Claude 방식).
  추천 요청 칩은 **빈 대화에서만**(결과마다 반복하지 않음).
- **모호한 요청은 되묻는다**: "더", "어엉"처럼 무엇을 할지 모르면 화면을 만들지 않고 예시와 함께 질문으로 답한다(파일·크레딧 없음).
  수정하라는 말인데 선택이 없으면 "먼저 선택해 주세요", 아직 못 하는 수정이면 할 수 있는 것을 안내. 대화 제목은 첫 **실제** 작업 요청으로 정한다.

## 코멘트 입구 하나로 (2026-11-20)
- 사용자: 보드 툴바의 말풍선이 상단 💬와 겹친다. → 디자인 파일 · 보드 하단 툴바에서 **코멘트 말풍선을 뺐다**.
- 상단 💬(또는 ⌘⌥M) = 오른쪽 코멘트 목록 + 코멘트 모드(위쪽 안내 띠, 캔버스 클릭 = 새 코멘트). 문서 편집기와 같은 규칙. Esc · ⌘⌥M · 💬 다시 누르기 · 다른 도구 고르기 = 모드와 목록이 함께 닫힌다.

## 하단 툴바 정리 (2026-11-20, "1-7" 툴바를 대체)
- 사용자 "피그마를 너무 따라한 듯, 딸깍넷에 맞게". 문제: Figma 용어(프레임 · 섹션 · 슬라이스 · 프로토타입 · 개발 모드), 눌러도 안 되는 "준비 중" 도구 5개, ▾ 묶음 4개, 그리는 도구와 화면 모드 스위치가 한 줄에 섞임, ⚡ 작업이 메뉴 검색과 같은 기능.
- **디자인**: `[선택 V] [손 H] │ [화면 F] [도형▾ 사각형 R · 타원 O · 선 L · 화살표 ⇧L] [텍스트 T] [펜 P] [이미지 넣기 ⇧⌘K]` (15개 → 8개, ▾는 도형 하나).
- **보드**: `[선택 V] [손 H] │ [스티커 메모 S] [사각형 R] [타원 O] [연결선 X] [텍스트 T] [펜 P] [구역 ⇧S]`. 두 툴바가 같은 모양 · 같은 크기 규칙(`useCompact` · `BAR_CLASS`).
- 옮긴 것: 디자인 · 프로토타입 = 오른쪽 패널 탭(원래 있음), 레이아웃 그리드 ⇧G · 개발 모드 ⇧D = 메뉴 ☰ › 보기(체크 표시). 섹션 = 보드의 "구역". 코멘트 = 상단 💬(⌘⌥M).
- 뺀 것: 크기 조절 · 슬라이스 · 다각형 · 별 · 벡터 펜(준비 중), ⚡ 작업(메뉴 ☰ 검색 ⌘K).
- 이름: 프레임 → **화면**, 연필 → **펜**(단축키 P, ⇧P도 동작), 이동 → **선택**, 손 도구 → **손**. 툴팁의 단축키는 모두 실제로 동작하는 것만 남겼고, 단축키 도움말(?)도 같은 이름으로 맞췄다. 메뉴 "벡터 › 펜(P)"은 "벡터 펜"(준비 중, 단축키 없음)으로.

## 코멘트 핀과 입력창 딸깍답게 (2026-11-20)

사용자 "너무 피그마 따라 했나". `uidesign/Comments.tsx`(UI 디자인, 문서 편집기 코멘트 공통).
